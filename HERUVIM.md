# ХЕРУВИМ на базе Open WebUI

Этот checkout является чистым upstream Open WebUI `0.11.0` с отдельным
пользовательским слоем для продукта «ХЕРУВИМ».

## Продуктовый принцип

Пользователь общается с одним цифровым советником. Выбор моделей, технические
параметры и внутренние специалисты не должны появляться в основном сценарии.
Ответы для руководителя строятся в порядке: суть, существенные риски,
рекомендация, основания и подробности по запросу.

## Что реализовано

- бренд и русская локаль по умолчанию;
- спокойная executive-палитра и увеличенный базовый масштаб интерфейса;
- новый стартовый экран с четырьмя управленческими сценариями;
- единый текстовый, голосовой и документный ввод;
- скрытие выбора модели после назначения модели по умолчанию;
- доступ к техническим controls только для администратора;
- собственный векторный знак `static/heruvim-mark.svg`.
- автоматическая регистрация RAGFlow как единственной модели «ХЕРУВИМ»;
- запрос ссылок и метаданных источников для каждого ответа RAGFlow;
- системный профиль executive-советника и безопасный конфигуратор ассистента.
- автоматическая синхронизация чат-вложений в datasets RAGFlow;
- единый канонический ID `heruvim:<sha256>` в Open WebUI и RAGFlow;
- восстанавливаемая фоновая очередь индексации и повторного запуска;
- пользовательский экран `/ingestion` с прогрессом, chunks и ошибками;
- обязательный протокол источников для существенных утверждений.

Если модель по умолчанию ещё не назначена, selector остаётся видимым. Это
аварийный путь первичной настройки; после выбора модели пользователь снова
видит только ХЕРУВИМа.

## Требования к запуску

- Node.js 18.13–22.x; рекомендуемая версия — Node 22;
- Python и остальные требования соответствуют upstream Open WebUI;
- для production задайте `WEBUI_NAME=ХЕРУВИМ` и `DEFAULT_LOCALE=ru-RU`.

## Подключение RAGFlow

Подробная инструкция по RAGFlow, OfficeCLI MCP и PDF MCP находится в
`HERUVIM_MCP_RUNBOOK.md`.

Полная установка с нуля, dev-режим, совместный Docker Compose и проверка всего
контура: [`INSTALL_RU.md`](./INSTALL_RU.md).

Каноническая схема маршрутизации текущих вложений, RAGFlow, редакторов,
выходных файлов и автоматизаций находится в `HERUVIM_DOCUMENT_PIPELINE.md`.

1. Создайте в RAGFlow chat assistant и подключите к нему нужные datasets.
2. Скопируйте `.env.example` в локальный `.env` и заполните только на машине
   владельца `HERUVIM_RAGFLOW_API_KEY`, `HERUVIM_RAGFLOW_CHAT_ID` и случайный
   `WEBUI_SECRET_KEY`. Для Docker оставьте `host.docker.internal`, при нативном
   запуске замените его на `127.0.0.1`.
3. Проверьте профиль без изменений:
   `python3 scripts/configure_heruvim_ragflow.py`.
4. Примените системный профиль к существующему ассистенту:
   `python3 scripts/configure_heruvim_ragflow.py --apply`.
5. Запустите продукт:
   `docker compose -p heruvim -f docker-compose.heruvim.yaml up -d --build`.

Compose использует прежний volume `heruvim_heruvim-open-webui-data`, поэтому
обновление образа не удаляет пользователей, историю и локальные настройки.

Скрипт использует частичное обновление `PATCH`, поэтому связанные datasets и
выбранная в RAGFlow модель сохраняются. Секреты никогда не записываются в git.

## Следующие продуктовые слои

1. Профиль владельца и прозрачное управление долгосрочной памятью.
2. Постраничное отображение цитат RAGFlow отдельной карточкой источника.
3. Независимый второй проход entailment-проверки каждого факта по источнику.
4. Поручения, утренняя сводка и журнал решений.
5. Контур подтверждения любых внешних действий.

Банковские операции, семейный мониторинг, MDM, камеры и государственные
сервисы не относятся к первому MVP и требуют отдельного security/legal
проектирования.
