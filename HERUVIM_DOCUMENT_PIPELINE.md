# Документный контур ХЕРУВИМа

Этот файл описывает фактическую маршрутизацию документов, запуск сервисов и
границы автоматизаций. Он является кратким каноническим документом; подробные
команды установки зависимостей остаются в `HERUVIM_MCP_RUNBOOK.md`.

## Главный принцип

Пользователь всегда работает в одном чате. Технический источник выбирается без
ручного переключателя:

| Запрос пользователя | Фактический маршрут |
| --- | --- |
| Обычный вопрос без документов | LLM без документных редакторов |
| «Изучи/прочитай этот файл» с вложением | локальный файл Open WebUI -> обязательное серверное чтение -> LLM |
| Изменить прикреплённый DOCX | DOCX Editor `9393` -> новый файл Open WebUI -> ссылки открыть/скачать |
| Изменить PDF или скан | PDF Editor/OCR `9394` -> новый файл Open WebUI -> ссылки открыть/скачать |
| Найти факт по базе/архиву/документам | LLM вызывает `ragflow_search` -> RAGFlow `9380` |
| Создать DOCX/PPTX/XLSX | DOCX Editor или OfficeCLI -> зарегистрированный файл Open WebUI |
| TXT/MD/CSV/JSON/XML/LOG | Gateway `9392`, с определением UTF-8/Windows-1251 |

Текущее вложение и индекс RAGFlow являются разными источниками. Чтение только
что приложенного файла не зависит от завершения индексации. Поиск по архиву не
читает случайный локальный файл.

## Загрузка документа

1. Open WebUI сохраняет исходный файл и его метаданные.
2. При `HERUVIM_RAGFLOW_SYNC_ATTACHMENTS=true` фоновая очередь зеркалирует файл
   в datasets RAGFlow. Повторная загрузка определяется по SHA-256.
3. Для текущего чата backend передаёт LLM только разрешённый локальный путь и
   при запросе на изучение сам выполняет чтение до финального ответа.
4. RAGFlow worker отдельно разбирает документ на chunks и выполняет OCR.
5. Состояние корпуса, просмотр исходника и удаление доступны во вкладке
   «База знаний».

`HERUVIM_OPENWEBUI_INTERNAL_FILE_PROCESSING=false` отключает второй встроенный
парсер Open WebUI. Это убирает дублирование: текущий файл читает MCP, архив
индексирует RAGFlow.

## Выбор инструментов

Все схемы редакторов больше не добавляются к каждому сообщению:

- `ragflow_search` остаётся доступным модели для вопросов по индексированному
  корпусу;
- чтение текущего вложения является обязательным backend-шагом;
- PDF Editor добавляется только при намерении изменить PDF/скан;
- DOCX Editor добавляется только при намерении создать/изменить DOCX;
- Gateway/OfficeCLI добавляется для PPTX/XLSX и других Office-задач.

Это защищает обычный чат от ложных tool calls и уменьшает служебный контекст.
При контрольном запуске простой автоматизации входной контекст уменьшился с
7384 до 3401 токена.

## Поддерживаемые операции

### DOCX

- чтение абзацев и таблиц;
- создание документа с заголовком, абзацами и таблицами;
- точная замена текста в абзацах и таблицах;
- сохранение форматирования runs вокруг заменяемого диапазона;
- OfficeCLI для расширенных операций с Office-документами.

### PDF и сканы

- нативное чтение текста;
- DeepDoc OCR с текстом и координатами;
- OCRmyPDF/Tesseract для добавления поискового слоя;
- точная замена, скрытие и добавление текста;
- визуальная замена текста на скане по OCR bbox;
- извлечение, удаление, поворот и объединение страниц;
- изменение метаданных;
- Unicode-шрифт и автоматическое вписывание длинной замены в исходный блок.

### Текстовые файлы

Gateway читает `.txt`, `.md`, `.csv`, `.json`, `.jsonl`, `.xml`, `.yaml`,
`.yml`, `.log` и `.rtf`. Проверяются `UTF-8 BOM`, `UTF-8`, `Windows-1251` и
`Latin-1`.

## Выходные файлы

После успешного создающего или редактирующего tool call backend:

1. копирует результат в Storage Open WebUI;
2. создаёт принадлежащую пользователю запись `File`;
3. прикрепляет нативную карточку файла к сообщению ассистента;
4. добавляет в результат `preview_url` и `download_url`;
5. просит LLM показать ссылки «Открыть» и «Скачать», не раскрывая локальный путь.

Ссылка требует авторизации Open WebUI. Для production задайте `WEBUI_URL` или
`HERUVIM_PUBLIC_BASE_URL` внешним HTTPS URL. Для локальных headless-задач
используется `HERUVIM_OPENWEBUI_BASE_URL=http://127.0.0.1:8080`.

## Автоматизации без интеграций

Автоматизация не является внешним cron-сервисом. Встроенный scheduler Open
WebUI:

1. забирает due-задачу из БД;
2. создаёт обычный чат владельца;
3. запускает тот же LLM/tool/document pipeline;
4. сохраняет ответ и `AutomationRun` с `chat_id`;
5. отправляет событие в открытый интерфейс через Socket.IO.

Поэтому без Slack, Telegram, email, webhook и terminal автоматизация всё равно
работает, но результат остаётся внутри ХЕРУВИМа. Внешнее действие или доставка
появляются только после подключения соответствующего tool server, terminal,
channel или webhook. При этом для генерации ответа всегда нужен доступный LLM
endpoint, а для документной задачи — соответствующий локальный MCP. Секреты
автоматизаций не следует помещать в prompt.

В пользовательском упрощённом интерфейсе управление автоматизациями скрыто.
Администратор сохраняет полный интерфейс Open WebUI и может включить разрешение
`features.automations` для выбранных ролей.

## Порядок запуска

### 1. LLM

Запустите OpenAI-compatible endpoint и задайте в `open-webui/.env`:

```dotenv
HERUVIM_LLM_BASE_URL='http://127.0.0.1:11434/v1'
HERUVIM_LLM_MODEL='model-id'
HERUVIM_LLM_API_KEY='...'
```

### 2. RAGFlow

Быстрый Docker-контур:

```bash
cd /Users/well/heruvim_ragflow/ragflow
./run_macos_m4.sh up
./run_macos_m4.sh status
```

Source/debug-контур описан в корневом `RUN.md`: инфраструктура, API `9380`,
worker и web запускаются отдельно.

### 3. Документные сервисы

В трёх отдельных терминалах:

```bash
cd /Users/well/heruvim_ragflow/ragflow
export PYTHONPATH="$PWD"
export OFFICECLI_BIN=/opt/homebrew/bin/officecli
bash ./tools/run_heruvim_gateway_mcp.sh --port 9392
```

```bash
cd /Users/well/heruvim_ragflow/ragflow
export PYTHONPATH="$PWD"
export OFFICECLI_BIN=/opt/homebrew/bin/officecli
bash ./tools/run_heruvim_docx_editor_mcp.sh --port 9393
```

```bash
cd /Users/well/heruvim_ragflow/ragflow
export PYTHONPATH="$PWD"
bash ./tools/run_heruvim_pdf_editor_mcp.sh --port 9394
```

`run_heruvim_document_mcp.sh` является отдельным MCP transport для отладки и
не нужен при штатном подключении трёх OpenAPI URL через интерфейс Open WebUI.
Launchers автоматически загружают `../open-webui/.env`. Для другого файла
задайте `HERUVIM_ENV_FILE`; для полного отключения загрузки задайте
`HERUVIM_LOAD_ENV=false`.

### 4. Open WebUI

Backend:

```bash
cd /Users/well/heruvim_ragflow/open-webui
/Users/well/.local/bin/uv run --frozen bash backend/dev.sh
```

Frontend:

```bash
cd /Users/well/heruvim_ragflow/open-webui
node_modules/.bin/vite dev --host --force
```

Открыть `http://localhost:5173`.

### 5. Подключения администратора

В Admin Panel -> Settings -> External Tools должны быть включены:

- `http://127.0.0.1:9392/mcp/openapi.json` — `heruvim-gateway`;
- `http://127.0.0.1:9393/mcp/openapi.json` — `heruvim-docx-editor`;
- `http://127.0.0.1:9394/mcp/openapi.json` — `heruvim-pdf-editor`.

Подключения глобальные. Пользователь не выбирает их вручную.

## Проверка

```bash
cd /Users/well/heruvim_ragflow/open-webui
bash ./tools/heruvim_doctor.sh
```

Затем проверьте четыре пользовательских запроса:

1. приложить PDF и написать «Изучи документ»;
2. написать «Найди по базе знаний ...»;
3. приложить DOCX и попросить точную замену с выдачей файла;
4. приложить скан PDF и попросить распознать/сделать поисковым.

## Безопасность

Порты `9392-9394` не имеют собственной пользовательской авторизации и умеют
работать с локальными путями. Держите их только на `127.0.0.1`; не публикуйте
через reverse proxy и не меняйте bind на `0.0.0.0`. Пользовательская проверка
доступа выполняется в Open WebUI, а ссылки на артефакты защищены его сессией.
